> 规范：`docs/design/开屏页重构.md`

## 主流程：刷新 `/` → 引导线扫动 → 信封落定 → 点击蜡封 → `/map`

## 关键断言（每条都能在录屏一帧内核验真伪）

- **互反色对角条带**：扫动结束的瞬间，沿引导线 100px 宽的带状区域里，原本的红色斜底色块呈灰、原本的暖灰底呈红；带外保持 Base Layer 配色。任何「带内外都是同色」的画面立即视为失败。
- **引导线无拐弯**：扫动过程中在开屏页视口内应始终为一根单段斜线，不出现任何可见的折点或竖直段。
- **大斜底色块不跳出**：初载页面过程中（SSR HTML 到 hydration 完成），红色 #c23643 斜底色块始终在位。不可出现先闪一下纯 #ece9e4 后才莫名其妙地「套上」红色块的闪屏。
- **几何中心点**：信封水平中心位于视口约 80% 宽度处、垂直 70% 高度处；目测应明显偏右下，而非居中或偏左。
- **滚动锁释放点**：在扫动 + 信封落定**之前**任何滚动操作都不会移动页面；落定后立即可滚。这一点会通过录屏中明显的「滑轮无效 → 滑轮有效」对比体现。
- **入场仅一次**：单次访问 `/` 内只播放一次扫动，不会因 Strict Mode / 路由回退在原地反复重播。

## 备注

- 测试通过浏览器原生交互完成，不使用 devtools 修改样式。
- 录屏覆盖步骤 1–6 单次连续走完；步骤 7 作为路由衔接附加片段。
- 移动端断点抽样：将浏览器宽度先后调到 ≥1280px / ≈768px 各拍一帧，确认信封像素宽度切换 (595/480) 后中心仍在 (80vw, 70vh)。
